# Internationalisation (i18n)

L'application est multilingue. La brique backend est le package officiel
[`@adonisjs/i18n`](https://docs.adonisjs.com/guides/digging-deeper/i18n) (formatage
ICU, chargement des fichiers, intégration VineJS) et le frontend Vue/Inertia consomme
les mêmes traductions via un pont léger.

## Langues supportées

Définies dans [`shared/types/i18n.ts`](../shared/types/i18n.ts) — source unique
réutilisée par le backend **et** le frontend. Deux listes distinctes :

- `SUPPORTED_LOCALES` — **langues de l'interface** (préfixe d'URL, sélecteur,
  `resources/lang`) : `fr` (défaut), `en`, `de`, `es`, `it`, `nl`, `pt`, `pl`, `sv`.
- `CONTENT_LOCALES` — **langues du contenu du catalogue** (produits, catégories,
  fournisseurs) : `fr`, `en`. Les fournisseurs ne saisissent leurs fiches qu'en
  français et en anglais ; une langue d'interface sans contenu dédié lit l'anglais
  (`contentLocaleFor`, `resolveTranslation`, recherche full-text).

Le premier élément de `SUPPORTED_LOCALES` est la locale par défaut.

**Politique de traduction du contenu (#75)** : le fournisseur saisit dans sa langue
source (`sourceLocale`) ; les autres langues de `CONTENT_LOCALES` sont générées
automatiquement (job Mistral), marquées « auto » (`is_auto`) et corrigeables. Une
correction manuelle n'est jamais écrasée. Voir [`catalogue.md`](catalogue.md). Le
périmètre à 32 langues est reporté à #84 (index plein texte).

**Ajouter une langue d'interface** : l'ajouter à `SUPPORTED_LOCALES` et à
`LOCALE_LABELS` (nom dans sa propre langue), un drapeau dans
`inertia/components/flag_icon.vue`, `og:locale` dans `shared/types/marketing.ts`,
les variantes régionales dans `config/i18n.ts`, une migration qui étend la contrainte
`users_locale_check` (cf. `1792100000000_extend_users_locale_check`), et le dossier
`resources/lang/<code>/` (mêmes fichiers que `fr`, hors textes juridiques).

**Textes juridiques** (`legal.json`, `privacy.json`) : uniquement en `fr` et `en`. Les
autres langues retombent sur l'anglais (`ENGLISH_FALLBACK_NAMESPACES`, appliqué dans
`inertia_middleware.ts`) tant qu'une traduction validée juridiquement n'existe pas.

**Drapeaux** : SVG inline (`flag_icon.vue`), affichés par le sélecteur
(`language_menu.vue`), le profil et les formulaires de traduction.

## Où vivent les traductions

`resources/lang/<locale>/<domaine>.json` — **un dossier par langue, un fichier par
domaine**. C'est la **source unique de vérité**, lue à la fois par le backend (via le
loader `fs`) et par le frontend (exposée en props Inertia).

```
resources/lang/
├── fr/
│   ├── common.json      # navigation, sélecteur de langue, nom de l'app
│   ├── auth.json        # pages connexion / inscription
│   ├── landing.json     # landing pages (accueil, contact, nav, footer, SEO)
│   ├── legal.json       # mentions légales (sections HTML rendues via v-html)
│   ├── privacy.json     # politique de confidentialité
│   ├── errors.json      # pages d'erreur (404, 500)
│   ├── emails.json      # sujets et corps des mails (côté serveur seulement, cf. docs/mail.md)
│   └── validator.json   # messages VineJS (clé "shared")
└── en/
    └── … (mêmes fichiers)
```

Format : JSON + syntaxe [ICU](https://formatjs.io/docs/core-concepts/icu-syntax/)
(interpolation `{name}`, pluriels, dates…).

Les clés suivent le motif `fichier.chemin.imbriqué` : `auth.login.title` cible
`resources/lang/<locale>/auth.json` → `login.title`.

> **Règle projet** : aucun texte visible en dur dans un template Vue. Toute chaîne passe
> par `t('clé')` et doit exister dans **les deux** fichiers de langue.

## Configuration

- [`config/i18n.ts`](../config/i18n.ts) : `defaultLocale: 'fr'`, `supportedLocales: ['fr', 'en']`,
  `fallbackLocales` (variantes régionales → base), formatter ICU, loader fs.

## Détection de la locale

[`app/middleware/detect_user_locale_middleware.ts`](../app/middleware/detect_user_locale_middleware.ts)
résout la locale par ordre de priorité :

1. Cookie `locale` (choix explicite du visiteur)
2. Préférence enregistrée sur l'utilisateur authentifié (`users.locale`)
3. En-tête `Accept-Language` (négociation de contenu)
4. Locale par défaut (`fr`)

La locale résolue est attachée à `ctx.i18n` et branchée sur VineJS
(`RequestValidator.messagesProvider`) → les messages de validation sont
automatiquement traduits.

## Changer de langue

- **Route** : `POST /locale` → `LocaleController.update` (nommée `locale.update`).
- **Validation** : [`app/validators/locale.ts`](../app/validators/locale.ts) (`vine.enum(SUPPORTED_LOCALES)`).
- **Effet** : pose le cookie `locale` (1 an), persiste `users.locale` si authentifié, puis
  `redirect().back()` pour re-rendre la page dans la nouvelle langue.
- **UI** : composant [`inertia/components/language_switcher.vue`](../inertia/components/language_switcher.vue)
  (intégré dans le layout), utilise `router.post('/locale', …, { preserveScroll: true })`.

## Pont backend → frontend

Le middleware Inertia [`app/middleware/inertia_middleware.ts`](../app/middleware/inertia_middleware.ts)
partage à chaque page :

- `locale` — locale active
- `supportedLocales` — liste des langues
- `translations` — dictionnaire plat ICU de la locale active (`i18nManager.getTranslationsFor(locale)`)

## Utilisation côté Vue

Le plugin [`inertia/i18n/index.ts`](../inertia/i18n/index.ts) est enregistré dans
`app.ts` et `ssr.ts`. Il expose `t()` de deux façons :

### Dans un template (propriété globale)

```vue
<template>
  <h1>{{ t('auth.login.title') }}</h1>
  <p>{{ t('common.greeting', { name: user.fullName }) }}</p>
</template>
```

### Dans le `<script setup>` (composable)

```ts
import { useI18n } from '~/i18n'

const { t, locale } = useI18n()
t('auth.login.title')
locale.value // 'fr' | 'en'
```

Le formatage ICU côté client s'appuie sur `intl-messageformat` (mêmes capacités
qu'`@adonisjs/i18n` : interpolation, pluriels…). Les formatteurs sont mémoïsés.
Une clé manquante renvoie la clé elle-même (l'oubli reste visible sans crasher le rendu).

## Mails

Les mails transactionnels sont rédigés dans la langue de leur destinataire : textes
dans `resources/lang/<locale>/emails.json` (9 langues), langue portée par la charge
du job. Voir [`docs/mail.md`](./mail.md#langue-du-destinataire). Les clés `emails.*`
ne sont pas envoyées au navigateur.

## Ajouter une traduction

1. Ajouter la clé dans `resources/lang/fr/<domaine>.json` **et** `resources/lang/en/<domaine>.json`.
2. L'utiliser via `t('<domaine>.<clé>')` dans le template ou le composable.

## Ajouter une langue

1. Ajouter le code dans `SUPPORTED_LOCALES` et un libellé dans `LOCALE_LABELS`
   (`shared/types/i18n.ts`).
2. Créer le dossier `resources/lang/<locale>/` avec tous les fichiers de domaine.
3. Ajouter la valeur à l'enum de la colonne `users.locale` (nouvelle migration).
